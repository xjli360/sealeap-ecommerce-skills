# 单位经济 / 佣金上限计算器

先用此页固定输入口径，再运行 [unit_economics.py](../scripts/unit_economics.py)。Python 3.9+，仅标准库；不需要API密钥，不连接店铺，也不修改佣金或广告。代码沿用本包MIT许可。

## 快速运行

从本Skill目录运行：

```bash
python3 scripts/unit_economics.py references/example-scenario.json
python3 -B -m unittest discover -s scripts -p 'test_*.py'
```

复制 [合成输入样例](example-scenario.json)，替换成你的数据，再把命令中的文件名换成新文件。也支持标准输入：`python3 scripts/unit_economics.py -`。结果以JSON写到标准输出，无文件覆盖副作用。

成功返回 `CALCULATED_SCENARIO`，退出码0；缺字段、未知成本、重复JSON键、币种对象混入金额、非有限数字、错误粒度等返回 `HOLD`，退出码2。`TARGET_MET`、`BELOW_TARGET`、`LOSS` 和 `NO_ORDERS` 是情景判断，不是数据真实性或平台批准证明。

## 统一粒度

一个文件只计算一个SKU、一个币种、一个分析窗口和一套单件收入/成本假设。一个可售单位可以是一包或一套，但输入中的一笔订单只能包含一个这样的单位。多SKU、多件购物篮或不同售价/履约成本先合理分摊并分成文件，不能直接把整单费用当每件费用。

分母是同一批**已支付并已发货订单**，包括这批订单后续发生的退款。不同时间发生的扣费、退款和佣金，要回归这批订单；当月所有退款不能直接扣本月新订单收入。预测时使用这批订单的预期值，未完成退货窗口的数据标为estimate。

`standard_affiliate`、`shop_ads_affiliate`、`non_affiliate` 是互斥订单组。一笔订单只能进入一组。不同达人、生效费率可建多个不同ID的组；脚本能检查重复组ID，不能验证源订单有没有跨组重复，须先按订单行去重。

## 输入字段

所有金额均为声明币种的主单位，推荐使用十进制字符串；汇率转换在输入前完成并记录日期。费率用0–1的小数，15%填`"0.15"`。未知填null会HOLD；只有确认不适用或明确假设为零时才填0。

| 字段 | 填写方法 |
| --- | --- |
| `site / currency / sku / period` | 实际站点、币种、匿名SKU、订单批次起止日期；预测窗口可以在未来 |
| `currency_minor_units` | 金额显示小数位，例如USD为2、JPY为0；脚本不联网校验币种表 |
| `input_kind / basis_note` | synthetic、estimate或actual；注明来源、优惠承担、退款成熟度和分摊假设。actual仅是输入声明 |
| `revenue_basis` | 固定为`seller_revenue_before_fees_excluding_pass_through_tax`；不能输入已扣费结算款或广告面板GMV |
| `unit_basis` | 固定为`one_paid_shipped_order_one_sellable_unit` |
| `unit_revenue.item_after_seller_discount` | 扣商家商品优惠后、退款和平台扣费前的应归卖家商品收入，剔除代收代缴税；卖家有权取得的平台补贴部分应正确包含在这里 |
| `unit_revenue.seller_shipping_income` | 实际归卖家的运费收入，已扣商家运费优惠；不能拿随后被平台冲销的运费展示额当收入 |
| `unit_revenue.additional_seller_incentives` | 未计入前两项、可归属本批订单的额外激励；已经包含在商品收入中的补贴不能再加 |
| `unit_revenue.refunds` | 本批订单的平均收入冲减，包括适用的补贴返还和运费退款；不是退货处理费 |
| `unit_inventory_recovery_credit` | 退回商品可再售的平均存货回收价值；不是现金收入，不得超过已计商品成本与头程之和 |
| `target_unit_contribution` | 每原始订单希望留下的贡献金额；0表示保本目标。若目标为留存收入的10%，先按本情景留存收入乘10%输入 |

`unit_costs`全部必填，均为每原始订单的平均费用：

| 成本键 | 范围 |
| --- | --- |
| `product / inbound / packaging` | 商品、头程、包装；赠送样品不计入正常订单商品成本 |
| `fulfillment / storage` | 正向履约和仓储；按实际方案及体积重量计算 |
| `platform_fee` | 退款返还后保留的平台交易费，**不含**下面单列的退款管理费；按实际账单或当前站点规则预估 |
| `refund_admin` | 退款管理费，包含适用封顶/豁免的影响；脚本不内置历史费率或上限 |
| `return_logistics / return_handling` | 逆物流、质检、处理等额外费用；商品成本已经计入，不能再次用“货损”重复扣除 |
| `nonrecoverable_tax / other` | 不可收回税费及其他变动费用；不含已在别处计入的佣金、广告和内容费 |

`campaign_costs`是**整个批次**的金额，不是单件金额：`samples`（赠样成本与寄送）、`creator_fixed_fees`（达人固定报酬）、`content_production`（制作与人力）、`other_fixed`。按各组订单数占比摊销；销量是预测值时，应另跑低销量情景。

每个`cohorts`分组必须包含：

| 字段 | 含义 |
| --- | --- |
| `id / channel / orders` | 唯一匿名组ID、上述三种路径之一、互斥的整数订单数 |
| `unit_commission_base` | 退款调整后、按实际联盟规则计算的平均计佣基数；不得擅自等同应归卖家收入或平台费基数 |
| `commission_rate` | 本批订单**实际生效**费率。Shop Ads没有单独费率而回退标准费率时，只填一次实际标准费率，不叠加两次 |
| `ad_spend` | 整组对应的投流支出；可包含没有成交的投流费用，不能只算成功订单的花费 |
| `basis_note` | 计佣基数来源、退款状态、保护期/生效费率、广告分摊说明 |

非联盟组的计佣基数和费率必须都为0。零订单也可保留已经发生的广告费；总订单为0时，固定成本留在总表的`unallocated_campaign_costs`，单件指标和费率上限为空。

## 公式与互斥条件

设`R`为单件应归卖家收入减退款，`C`为单件非佣金成本减存货回收，`F`为批次固定成本，`N`为总订单，`T`为目标单件贡献。组`j`的计佣基数总额为`Bⱼ`，实际费率为`rⱼ`，广告费为`Aⱼ`，订单数为`nⱼ`。

```text
分组固定成本 Fⱼ = F × nⱼ / N
分组贡献 = (R − C) × nⱼ − Fⱼ − Bⱼ × rⱼ − Aⱼ
目标佣金上限 = [(R − C − T) × nⱼ − Fⱼ − Aⱼ] / Bⱼ
当前佣金下的广告上限 = (R − C − T) × nⱼ − Fⱼ − Bⱼ × rⱼ
佣金与广告共同预算 = (R − C − T) × nⱼ − Fⱼ
```

保本佣金上限令T=0。可用余额为负时，返回`feasible=false`和空费率，表示零佣金也达不到目标；不会把它截成“可设置0%”。计佣基数为0时不返回无穷大佣金率。

佣金费率向下截断至0.01个百分点，广告金额上限向下截断至币种小数位；这是保守数学输出，**不是后台支持的费率精度或区间**。其他金额只在显示时四舍五入，计算过程保留十进制精度。

**不能同时采用两种上限**：佣金上限固定当前广告费；广告上限固定当前佣金。任何调整后，佣金与广告的合计仍须不超过共同预算。`uniform_*_commission_cap`表示对所有联盟组采用同一费率时的总盘经济上限，不代表各组都会达到目标，也不替代各组上限。

这些上限是在订单量、退款和成本不变的情景下算出的，不预测加预算会带来多少订单；`max_per_order`不是增量获客成本。调整佣金、售价、广告或预测销量后应重新计算。

## 合成样例的预期结果

| 指标 | 结果 |
| --- | ---: |
| 留存卖家收入 | 3,800.00 USD |
| 非佣金变动成本 | 1,800.00 USD |
| 寄样、报酬和制作等固定成本 | 200.00 USD |
| 达人佣金 / 广告费 | 468.00 / 240.00 USD |
| 总贡献 / 单件贡献 | 1,092.00 / 10.92 USD |
| 标准组目标佣金经济上限 | 38.88% |
| Shop Ads组目标佣金经济上限 | 22.22% |
| 全部联盟组统一费率的目标经济上限 | 32.22% |
| 目标贡献下佣金与广告共同预算 | 1,400.00 USD |

以上完全虚构，用于核对程序，不是建议采用的费率或经营结果。

## 算完之后

按[当前官方规则](evidence.md)核对本账户的协作模式、允许区间、费率联动和保护期。例如所核读的美国站Open Collaboration说明涉及Shop Ads费率相对标准佣金的下限；这个平台下限若高于经济上限，就没有可行交集。保护期内仍按旧费率计算，不能提前使用尚未生效的降佣。

工具只给情景贡献，不给银行到账、完整会计利润或GMV Max增量ROAS；税、费率和归因规则都不自动查询。金额上限、最多100分组及总订单上限是输入保护，不是平台限制。真实订单、达人身份、原始账单和凭证保存在私有目录。
