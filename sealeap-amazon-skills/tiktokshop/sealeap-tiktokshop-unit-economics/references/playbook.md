# 判读手册

本页是针对本任务独立整理的M执行设计；来源只支持[证据文件](evidence.md)注明的范围。

## 决策边界

- 商家自产内容也有人力成本；达人佣金与广告费不可互相替代。
- 优惠由谁承担必须核实，平台补贴不能一概当卖家成本或额外利润。

## 输入缺口怎样影响结论

本任务需要：实际平台费率、订单净额、履约、佣金基数、样品/报酬、广告和售后。

把缺口关联到具体判断：缺真实费用则不给精确利润；缺事件数量则不推转化；缺权限或平台能力则不宣称能执行。已有数据足以完成某部分时继续，不为等一项资料阻断全部工作。以观察性证据提出的原因写为“待验证假设”。

## 执行计算与复核

按[计算器说明](calculator.md)映射输入并运行脚本，保留原始输入和JSON结果。先核佣金路径与退款基数，再核模型输出；经济上限与平台允许费率、生效状态分别交付。脚本不计算现金到账，现金事项继续单列。

## 可交付模板

| 交付项 | 填写内容 |
| --- | --- |
| SKU贡献表 | 对应对象与范围、具体结果、依据/口径、未知项及下一步 |
| 佣金/投流上限 | 对应对象与范围、具体结果、依据/口径、未知项及下一步 |
| 现金情景 | 对应对象与范围、具体结果、依据/口径、未知项及下一步 |

保留与结论相关的明细及观察日期；对外输出用匿名对象代号。收费、资格、时限和控制项以实际市场当期规则为准，不能填固定行业常数代替账户事实。

## 易错场景（合成）

合成：净收入40，商品与履约22、平台/佣金8、内容2，广告前贡献8，不能按18元算获客上限。

合成：佣金与广告共同预算1400，固定当前广告240时可留1160给佣金；固定当前佣金468时可留932给广告。不能同时使用1160佣金和932广告。

合成：某组经济佣金上限8%，平台适用下限10% → 无可行交集，不能直接把8%作为上线费率。

## 完成标准

流程中的每个主要判断都能落到上述交付项，未通过的条件有明确补证或停止动作。需要变更时提供目标、前后值、作用范围、验证和恢复办法；纯分析任务到此交付，不暗中扩成账户操作。
