# 操作手册

以下分支、数据字段和合成案例为M（模型独立综合）；E与R的有限支持范围见 [证据文件](evidence.md)。

## 分支判断

| 观察情况 | 下一步 | 必须避免的误判 |
| --- | --- | --- |
| 数量总和正确但目的仓错误 | 仍判失败 | 不能只做全计划总数量校验 |
| 重复箱标 | 定位所有受影响箱重新核对 | 不能仅给第二箱改一个内部名字 |
| 脚本通过但实物未盘点 | 保留实物未知状态 | 数据一致不是装箱事实证明 |

## 交付工作表

| 交付项 | 必须保留 |
| --- | --- |
| 计划/实装差异表 | 对象与版本、事实/口径、结论、未知项、负责人和下一次验收 |
| 箱与收货标签矩阵 | 对象与版本、事实/口径、结论、未知项、负责人和下一次验收 |
| 离线核对结果 | 对象与版本、事实/口径、结论、未知项、负责人和下一次验收 |
| 待人工复核的实物和扫码项 | 对象与版本、事实/口径、结论、未知项、负责人和下一次验收 |

每个状态都写观察时间；没有发生的动作使用“拟议/待核”，不能写“已完成”。公开报告用匿名代号，原始账户、订单和客户资料留在用户授权范围内。

## 合成案例

### 场景1

输入：合成：计划A6件、B4件；两箱各A3/B2。

应有处理：数量通过，但还需独立核仓、箱标与实物。

### 场景2

输入：两箱数量都正确却使用相同收货标签。

应有处理：必须失败并核实际标签，不能按总量正确放行。

### 场景3

输入：一箱分配FC-A却准备发往FC-B。

应有处理：即使SKU总数对平也不能放行。


## 验收与停止

逐项检查交付是否能追到输入事实。遇到身份不匹配、决定性字段缺失、许可不足或超出用户授权时，停止受影响动作，列明补证与可继续部分。对批量变更保留目标清单、前后值、作用范围和恢复办法；单次请求成功不替代实际结果。
