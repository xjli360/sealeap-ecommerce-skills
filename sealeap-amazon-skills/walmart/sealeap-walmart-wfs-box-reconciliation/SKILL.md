# Walmart WFS 箱内明细与数量核对

## 输入与范围

- 每个shipment与SKU的计划数量及目的仓。
- 每箱ID、实际SKU/数量与收货标签标识。
- 箱/托盘层级及最终实际装箱记录。
- 源表版本、打印版本和承运交接时间。

先固定目标市场、观察时间与用户要作的决定。缺少决定性资料时完成可确定部分，把其余标为未知或HOLD，不虚构账户状态。

## 工作流程

1. 冻结最终计划与实际装箱版本，分别保留shipment、目的仓、箱和SKU身份。
2. 核每箱标签对应真实内容，收货标签不能在多个箱重用；商品SKU可重复出现在不同箱，数量必须聚合对平。
3. 逐shipment与SKU比较计划和实装总数，检查漏装、超装、未知商品和跨仓错配。
4. 需要重复核查时运行随附离线脚本；工具只检查输入结构与一致性，不验证GTIN真实性、条码可扫性或实际箱内实物。
5. 修正后重新核对并确保打印版本匹配；未解决错误不得将清单当成可直接发货指令。

## 交付

- 计划/实装差异表。
- 箱与收货标签矩阵。
- 离线核对结果。
- 待人工复核的实物和扫码项。

分支判断、验收字段和合成案例见 [操作手册](references/playbook.md)；需要查来源范围、计数或当前规则时读 [证据与规则](references/evidence.md)。

## 离线核对

需要核对装箱JSON时，先读[输入合同与运行方法](references/manifest-schema.md)，再运行 [核对脚本](scripts/check_box_manifest.py)。它只检查本地输入，不是平台上传器。

## 执行边界

本Skill提供任务流程，不表示已经连接平台或取得商户操作权限。事实、估算、假设、未知分别记录；经验与模型输出不保证收益。只执行用户已授权动作，已有明确授权不重复索取；提交、处理和结果回读分开。网络和工具受限时完成可审阅方案，不绕过访问限制或伪造执行成功。
