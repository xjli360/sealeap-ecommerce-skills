# 搜索洞察、报价与目录诊断

X04 提供分阶段检查的启发，BL02 的可见讲义提示报价与履约因素，BL01 支持核对广告商品身份。下面诊断表为 M；数据定义用 R16/R17 校正，见 [证据与规则](evidence.md)。

## 先写报告口径

| 指标/报告 | 口径区别 | 使用限制 |
| --- | --- | --- |
| Sales rank | 商品类型内、过去六个月订单；有历史与成交要求 | 新品无排名不等于零需求 |
| Search funnel rank | 同商品类型、选定时段的曝光/点击/加购排名；每周更新 | 排名差不能计算CTR/CVR |
| Query report | 周或月，查询级曝光/点击/加购份额、频次排名等 | 只覆盖搜索，不能代表全渠道 |
| 变体 | 同变体组可能共享排名 | 同组排名不能当多个独立竞争样本 |

商品的 Query Score 与整个查询的 Frequency Rank回答不同问题。份额表示在对应竞争集合中占比，点击份额不等于本商品点击/曝光。保持各指标原名称、窗口和分母；未提供事件数量时不补算转化率。

## 从异常到待核假设

曝光排名弱：检查商品类型、查询相关性、索引和可售状态。
曝光相对好而点击弱：检查意图、主图、报价、交付与竞争集合。
点击有信号而成交弱：核库存、变体、页面事实、服务条件与实际购买阻力。
这些是检查方向，不是对原因的确定归因；不同排名之间不能推算“漏掉多少订单”。

## 内容、Offer和身份分别验收

内容层核商品类型、属性和被采纳字段；Offer层核含运费报价、配送、库存稳定、Buy Box与店铺表现；身份层核卖家SKU、平台商品ID、变体组和广告商品是否正确关联。一个平台上的ID不能直接当另一个平台的ID。

保存“提交内容、后台处理、前台采纳、商品可售、广告可用”的各自状态。Feed成功不保证前台采纳，选中广告商品不证明活动交付成功。

## 改动复盘

一个主要假设对应一次可解释改动。记录同周期库存、价格、广告和促销；平台提供的前后观察窗口只能支持变化观察，不能消除这些干扰。优先比较同报告、同商品身份、同口径数据，缺口保留未知。
