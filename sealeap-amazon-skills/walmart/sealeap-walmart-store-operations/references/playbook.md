# 操作手册

以下流程细化、计算和合成案例均为 M（模型综合设计），来源支持范围见 [证据与规则](evidence.md)。

## 当前面板与旧资料
本次核验的官方2026版Listing Quality有五项；目录级分数是商品级分数的平均，不等于流量加权转化表现。N/A表示该项不计入，不应补成零。
对内容质量和总体质量分别描述；不能因为图片齐全，就称全部运营健康。

## 修复顺序（M）
| 层次 | 需要验证的事实 | 常见动作 |
| --- | --- | --- |
| 身份与可售 | GTIN/商品一致、状态原因 | 修正映射或补有效资料 |
| 内容 | 正确类型、属性、图片、可采纳权限 | 有依据地修改具体字段 |
| 报价 | 到手价、促销、Buy Box状态 | 在利润底线内测试 |
| 履约 | 实际可售库存、交期、邮编覆盖 | 修库存/承诺与补货 |
| 售后 | 退货与差评原因 | 改产品、包装或说明 |

## 三层验证
提交接口或feed receipt证明请求已接收；处理结果证明后台接受了哪些字段；前台页面证明买家看到什么。三层分别记状态，不以HTTP成功或feed没有报错代替内容落地。
内容被其他贡献者覆盖时保存证据并走当期支持流程，不批量制造新商品绕开目录问题。

## 库存与现金
安全库存要结合真实日销量区间、补货交期与波动，断货天不作为零需求。WFS与自发货库存分开，预留和在途不能直接当可售。
降价清理慢动库存要算回收现金与继续仓储的差异，不因毛利率下降就一律拒绝，也不因销售额上涨就宣布成功。

## 示例（合成）
feed显示完成，但标题未变且账户无对应内容权限。应报告“提交完成、前台未采纳”，核对内容权限；不能说优化已上线。
