# Walmart 目录、报价与履约运营

将任务转化为有证据、成本边界和验证办法的经营决策。来源研究日期：2026-09-23；使用时核验所在站点当前规则。

## 输入

站点、SKU/item ID对照、当前商品状态和质量分项、feed结果、前台页面、内容权限、价格/库存、配送与退货数据。导出时清除买家和非必要账号信息。

## 工作流

1. 先确认SKU与item身份、发布状态、目标地区可购和库存，再分析内容及流量；类目或商品身份错配不能靠加关键词补救。
2. 按当前R14面板逐项拆分内容质量、价格竞争力、配送、发布与有货、评分与评论。W04 的旧概括只作问题分类启发；N/A不当零分。
3. 内容变更不生效时检查feed是否处理、属性映射、权限与被采纳内容。品牌所有者/授权转售者优先等机制可能影响发布，重复上传不等于解决。
4. 比较买家到手价、Buy Box/报价状态和目标邮编交付；低价必须受贡献底线约束。W01 支持把商品与履约准备放在投放前。
5. 将缺货、迟发、取消、退货按SKU和时间复盘，区分仓内、运输、承诺设置或商品本身问题。
6. 交付字段级修复草稿；已有授权时执行最小变更并回读feed、后台和前台，记录未生效项与下一步证据。

## 交付

SKU/item映射、可售状态、五项质量问题、内容采纳差异、报价/库存/履约动作和逐项回读结果。

## 证据与执行边界

网络来源只支撑参考文件列出的有限方法；其余步骤、公式、示例和决策条件是 M（模型综合设计），不是作者原话、平台保证或已验证业绩。事实、估算、假设、未知分开记录；互动量不证明经营效果。

仅在用户已授权范围内执行。诊断请求不自动授权投放、采购、上架或联系他人；已明确授权无需重复征求同一许可。执行时保留目标、前后值、结果与回读证据。工具不可用时完成数据模板和方案，不伪造后台操作成功。
