# Walmart 官方评价计划资格与预算

## 输入与范围

- 目标站点与后台实际可见子项目、条款版本、当前价格报价和参与状态。
- 商品身份、发布/库存/成交/评价/内容质量数据，以及后台资格提示。
- 可承受费用、目标数量、履约与商品成本；未知费用保持未知。
- 已参加项目的目标、实际评价、账单、退出记录和后续费用。

官方评价项目的资格、预算与账单；与客服评价分析及广告投放分开。先固定站点与观察日期；事实、估算、假设和未知分开记录。缺决定性资料时完成可确定部分，把其余列为待核或 HOLD。

## 执行流程

1. 区分 Post-Purchase Reviews 与 Recognized Reviewer；先确认账户真实可用项目，再读取对应规则，不能把同一品牌名下的资格和收费互相套用。
2. 建立 SKU 候选表，核对后台资格与商品可售、库存、订单和评价数据；符合部分公开条件不代表已被项目接受。
3. 把待改商品事实、质量与售后问题先列出。评价计划应收集真实体验，不能用来遮掩缺陷、筛选好评人或承诺星级。
4. 按当前报价建立零产出、部分完成和达到目标三种成本情景，列出商品/履约/激励/服务费用的已知与未知；目标数不当作保证产出。
5. 交付有限参与方案及停止条件。只有具备所需授权并完成适用条款确认时才提交参加，随后回读 enrolled 等实际状态。
6. 定期将实际发布评价、收费、退出与尾部结算对账；退出不直接等于已结清，也不能因出现差评就要求平台删除。

## 交付与验收

- 子项目资格与 SKU 候选表。
- 费用分项与零/部分/完成情景。
- 参与、停止与尾部结算计划。
- 真实评价反馈与商品改进记录。

分支、模板和合成案例见[操作手册](references/playbook.md)；需要核对内容依据与当期规则时读[证据与规则](references/evidence.md)。单个任务只加载所需参考。

## 执行边界

输入、决策流程与案例属于 M（模型综合）；来源不保证经营效果。本 Skill 不表示已连接商户后台。按用户已授权范围执行，已有授权不重复索取；涉及条款或交易的确认按宿主要求处理。提交、处理与实际生效分别验收，工具不可用时交付可审阅方案，不伪造已完成结果。
