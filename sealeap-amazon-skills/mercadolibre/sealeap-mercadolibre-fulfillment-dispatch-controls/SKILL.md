# 美客多订单履约与交接控制

## 任务与输入

- 站点、账户模式、订单/包裹ID、承诺时间和账户时区。
- 真实SKU/数量、可用库存、平台指定渠道或自有物流资格。
- 面单、交接扫描、追踪状态、异常与买家消息。

先固定国家站、经营/物流模式、币种和观察日期。将事实、估算、假设与未知分开；缺关键资料时完成可确定部分，把受影响的判断留待补证。

## 工作流程

1. 先辨认履约责任由谁承担，按订单实际路线核发货要求；Full的仓库动作和卖家直邮动作分开。
2. 连接订单、包裹、SKU和数量，检查当前面单及库存，避免多订单/多包裹混用身份。
3. 将生成面单、完成包装、交承运、在途和妥投分别取证，核当前截止时间与异常责任。
4. 形成当日行动队列；库存或时间不足时先给真实处理方案，在授权范围内操作并回读，不靠虚假追踪掩盖延误。

## 交付

交付按截止时间排序的履约队列、交接缺口及异常处理记录。

遇到条件分支、字段设计和误判场景时读[操作手册](references/playbook.md)；核查来源实际支持范围和当期规则时读[证据与规则](references/evidence.md)。

## 执行范围

本包的流程、模板和算例为 M（模型综合），不表示已接入美客多或验证经营收益。只执行用户已授权的动作，已有授权不重复索取；变更需明确对象、前后值、实际能力与回读办法。工具不可用时交付方案和输入需求，不伪造已生效结果。
