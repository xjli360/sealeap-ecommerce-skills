# eBay 商品、履约与店铺运营

将任务转化为有证据、成本边界和验证办法的经营决策。来源研究日期：2026-09-23；使用时核验所在站点当前规则。

## 输入

目标站点、商品事实/检测记录、当前Listing、库存、报价与物流承诺、访问与成交数据、退货和客服原因。隐去买家身份与完整订单号。

## 工作流

1. 先核实商品身份、可售库存和真实性，再判断可发现性。B02 提供标题、属性、图片和价格的联合检查框架。
2. 标题表达型号与关键辨识信息；item specifics 逐项取真实值，缺失标待确认。汽配/电子兼容性须有具体适配依据。
3. 用真实图片交代成色、缺陷和包含物，确保描述、图片与类目condition一致。不能以美化修图隐藏损伤。
4. 比较商品价+运费的总到手价、处理时间、配送覆盖与退货条件。库存联动按唯一SKU和实际数量对账，避免多渠道超卖。
5. 将低曝光、低点击、低成交、迟发和退货分别定位，按损失与影响排序；B04 只作为搜索表达的补充依据。
6. 交付字段级修改草稿与履约问题动作。在线修改后需确认前台内容与库存，不能把提交成功当展示已更新。

## 交付

逐字段前后值、事实依据、成色/兼容性缺口、履约与退货问题表、优先级和复查日期。

## 证据与执行边界

网络来源只支撑参考文件列出的有限方法；其余步骤、公式、示例和决策条件是 M（模型综合设计），不是作者原话、平台保证或已验证业绩。事实、估算、假设、未知分开记录；互动量不证明经营效果。

仅在用户已授权范围内执行。诊断请求不自动授权投放、采购、上架或联系他人；已明确授权无需重复征求同一许可。执行时保留目标、前后值、结果与回读证据。工具不可用时完成数据模板和方案，不伪造后台操作成功。
