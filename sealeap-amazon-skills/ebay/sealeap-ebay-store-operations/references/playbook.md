# 操作手册

以下流程细化、计算和合成案例均为 M（模型综合设计），来源支持范围见 [证据与规则](evidence.md)。

## 商品表达
| 字段 | 通过条件 | 拒绝的捷径 |
| --- | --- | --- |
| 标题 | 精确型号、关键规格、正确成色 | 无关品牌或夸大词 |
| 属性 | 取自实物或可信规格资料 | 用猜测填满字段 |
| 图片 | 全貌、标签、关键部位、瑕疵 | 借别人的图替代实物 |
| 兼容性 | 具体型号与匹配依据 | “通用所有型号” |
| 发货地/时效 | 与实际仓库和承运能力一致 | 虚构本地发货 |
| 退货 | 条件清楚，处理可执行 | 隐藏费用或误导承诺 |

## 经营复盘（M）
把访问变化、购买变化和退货变化独立画出。修改商品表达与调价同日发生时，不能将销量变化归因于单一动作。
按取消、晚交运、未收到、与描述不符、功能故障等原因分组。一个SKU反复发生同类问题时先修商品和供应，不用扩大广告掩盖。
多渠道售卖时，扣减失败、预留未释放和SKU映射错误分别检查。只有可售在手库存可支持当前交付承诺；在途库存需明确到货风险。

## 消息与执行
需要回复买家时先拟与订单事实一致的草稿；发送必须有明确授权。争议材料只提交真实订单、承运和商品记录。
变更应列 listing ID 的脱敏别名、字段、旧值、新值、依据与回读结果。报告不公开完整交易号或买家信息。

## 示例（合成）
商品被退回原因是“少配件”，但标题写套装、图片也展示配件。先纠正包含物和图片，并处理库存实际配置；降价不能修复误导。
