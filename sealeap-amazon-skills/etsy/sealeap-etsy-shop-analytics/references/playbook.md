# 判读手册

本页是针对本任务独立整理的M执行设计；来源只支持[证据文件](evidence.md)注明的范围。

## 决策边界

- 不同报表存在归因差异，订单可能重叠，不能直接相加。
- 收藏和评价不是订单；缺销售数据不能补推转化。

## 输入缺口怎样影响结论

本任务需要：统计窗口、流量/访问定义、订单净额、商品状态、广告/促销与制作产能。

把缺口关联到具体判断：缺真实费用则不给精确利润；缺事件数量则不推转化；缺权限或平台能力则不宣称能执行。已有数据足以完成某部分时继续，不为等一项资料阻断全部工作。以观察性证据提出的原因写为“待验证假设”。

## 可交付模板

| 交付项 | 填写内容 |
| --- | --- |
| 指标字典 | 对应对象与范围、具体结果、依据/口径、未知项及下一步 |
| 变化拆解 | 对应对象与范围、具体结果、依据/口径、未知项及下一步 |
| 行动优先级 | 对应对象与范围、具体结果、依据/口径、未知项及下一步 |

保留与结论相关的明细及观察日期；对外输出用匿名对象代号。收费、资格、时限和控制项以实际市场当期规则为准，不能填固定行业常数代替账户事实。

## 易错场景（合成）

整体收入增加却制作超时和退款上升，应看履约后的贡献，不能只扩广告。

## 完成标准

流程中的每个主要判断都能落到上述交付项，未通过的条件有明确补证或停止动作。需要变更时提供目标、前后值、作用范围、验证和恢复办法；纯分析任务到此交付，不暗中扩成账户操作。
