# 投放商品分组与测试判读

X02 提供少量商品测试、点击与成交分开看的思路；不采用其中固定CTR、周期或放量百分比。以下设计为 M；实际控制项由 R03/R04 约束，见 [证据与规则](evidence.md)。

## 先界定平台能控制什么

站内广告按当前可用的日预算和商品开关管理。可以给商品打内部测试标签，却不能把这个分析标签写成平台支持独立商品日预算、逐关键词出价或否词。站外广告另看资格、费率与归因，不与站内点击费用混成一个模型。

按相近购买任务、贡献空间和交付能力选择可比较商品。总预算增加时，实际花费不会必然均匀分到每款；用实际交付数据复盘，不把计划分配当实际支出。

## 一张测试记录足够保留关键差异

记录商品代号、购买任务、主图版本、报价/交付、纳入日期、可见曝光和点击、广告花费、归因订单、退款及制作成本。附归因窗口和缺失字段；店铺汇总数不能伪装成单商品指标。

| 现象 | 待核假设 | 后续动作 |
| --- | --- | --- |
| 曝光少，CTR不稳定 | 可达流量或相关性不足 | 查商品资格、词义与投放实际状态 |
| 点击已有但订单少 | 报价、交付或定制摩擦 | 检查页面承诺，形成单一改动测试 |
| 归因收入增加但贡献下降 | 低毛利组合、返工、费用或退款 | 先按商品核算再决定放量 |
| 自然与广告订单同时增长 | 旺季、促销或商品共同变化 | 保留观察性结论，不宣称增量 |

少量点击里的零单不证明商品无需求；高CTR也不证明长期盈利。不要比较不同窗口、不同变体或不同费用范围的比例。

## 继续、修改或停止

在测试开始前写累计损失上限、最低可接受净贡献和结束条件。数据不足且未触及边界，可保持有限观察；触及损失边界就停止当前测试并复盘；有成熟净贡献证据、产能和库存余量才考虑扩大。预算调整幅度由风险容量决定，不套固定百分比。

自然单与广告归因单的占比只描述报表结构，不是平台认可度或商品真实性的证明。订单级无法去重时，不把两种报表销量直接相加。
