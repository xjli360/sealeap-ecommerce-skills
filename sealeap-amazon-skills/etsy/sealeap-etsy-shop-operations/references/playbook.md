# 操作手册

以下流程细化、计算和合成案例均为 M（模型综合设计），来源支持范围见 [证据与规则](evidence.md)。

## 一次诊断一层
| 现象 | 所需证据 | 修改重点 |
| --- | --- | --- |
| 搜索流量少 | 真实搜索词、分类与属性 | 修正不匹配语义 |
| 有展示少点击 | 主图、标题、同类报价 | 信息可辨识与差异 |
| 有访问无订单 | 规格、交期、价格、个性化难度 | 降低购买不确定性 |
| 订单多但差评增 | 质量、沟通、履约记录 | 修正产品和交付 |
| 数字品退单多 | 下载、格式、许可说明 | 让购买前后信息一致 |

## 内容写法（M）
关键词簇按收礼人/用途/场景/商品类型构建。选择后台当前允许的相关标签与属性，不把字符数、标签数、排名信号永久写死。不要承诺广告或会员身份一定提高自然排名。
先列已验证事实，再将事实转为标题、描述与图片说明；未经验证的耐用、医疗、环保等声明保持未知。

## 定制与售后
工时和排队量决定处理时间。给每单记录：客户需求已收齐→校样已确认→制作→质检→发货。客户未确认不等于可以默认替其决定关键规格。自动回复草稿须说明下一步；对外发送依据已有授权。
评价分析只汇总问题类别，不公开买家姓名、订单编号、地址或私信。不得诱导只留好评、刷单或编造收货证明。

## 示例（合成）
搜索词是“可编辑模板”，商品却只提供固定PDF。应修正产品提供方式或纠正关键词，不能继续用热词引流后在描述末尾隐藏限制。
