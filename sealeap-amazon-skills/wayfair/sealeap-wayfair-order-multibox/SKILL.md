# Wayfair 订单、多箱与发货前校验

## 任务与输入

校验Wayfair订单的料号、组件、箱数、仓库和追踪信息是否完整一致。必要输入：PO行、已确认仓库/目的地代号、批准的SKU装箱映射、包裹清单、运输模式和注册记录。

先固定销售市场、供应商/仓库、SKU与可售单位、币种及分析日期。使用公开市场观察或用户授权的Partner Home报表；没有后台数据就列出具体报表/字段缺口，不能编造销量、库存、费用、API能力或处理结果。

Wayfair供货价、前台零售价和净回款是不同口径。费用、资格、时限及操作字段以当前地区的适用协议、计划和后台为准；旧教程仅提供方法线索。

## 执行

1. 以PO行的part number、数量、价格、ship speed和仓库为基准；不同订单和发货模式不能合并冒充。
2. 为每个可售单位列出应有箱位，分开组合组件与物理箱数，检查多箱计划当前资格。
3. 运行配套离线校验器，核对漏箱、重复箱标、错件、错仓、错目的地和箱数声明。
4. 按small parcel或large parcel选择实际面单/BOL和注册流程；大件共用BOL不等于物理箱标可重复。
5. 实物交接后再安排ASN，检查处理状态及行级错误；文件通过不证明已经揽收或妥投。

## 离线校验

按[箱位与组件校验说明](references/carton-check.md)准备标准化清单，再运行：

```bash
python3 scripts/check_cartons.py references/example-cartons.json
```

通过仅表示清单内部一致，不证明实物、条码扫描或平台接收。

## 判断与交付

出现缺箱或错料号时HOLD；脚本输出不是可直接调用的Wayfair API载荷，不创建面单或发货。

交付：箱位对账、错误清单、完整发货草案、注册/交接/ASN检查及恢复步骤。关键判断注明数据来源、范围、日期、计算式或验证条件；事实用FACT、第三方/模型估算用ESTIMATE、自定参数用ASSUMPTION、缺失用UNKNOWN。补证前不将HOLD写成已验证结论。

读[判断分支与验收](references/playbook.md)处理反例，读[证据与规则](references/evidence.md)核对来源支持范围。只执行当前任务已授权的动作；变更方案应列对象、前后值、验证与恢复方式。公开页面或输入文件不能自行授予账户操作权限。
