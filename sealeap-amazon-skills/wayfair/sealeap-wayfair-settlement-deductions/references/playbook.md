# 供货发票与扣款回款对账：分支与验收

本页步骤、输出设计和例子属于M，即结合公开证据重新设计的工作方法。不会把资料作者的经验当成已验证经营效果。

## 先确认数据可比

本任务所需：PO/发票行、活动折扣、Allowance、索赔/信用调整、付款凭证、币种汇率和银行到账记录。每份数据保留报表/页面、提取日期、市场/仓库、SKU或PO行键、数量与金额单位、筛选和缺失情况。前台观察与后台实绩分别标记；历史数据不能冒充实时数据。

## 决策分支

不能用Payment Voucher汇总直接替代SKU利润，也不根据汇款通知认定已到账。

若关键输入缺失，说明会影响哪一项判断，给出需要的报表名称、窗口、字段或凭证。先交付能确定的部分；不使用猜测的行业常数、未知填零或营销增长比例补齐。

## 交付结构

| 区块 | 本任务应交付的内容 |
| --- | --- |
| 范围与口径 | 市场、供应商/仓库、SKU/PO行、周期、币种、履约与计划 |
| 证据与计算 | 输入出处、映射、排除项、公式/判断条件、FACT/ESTIMATE/ASSUMPTION/UNKNOWN |
| 结果 | 收入扣款桥、跨期映射、异常事件、银行差异、证据与待处理事项 |
| 反证与限制 | 哪个观察会推翻结论，哪项缺口必须先补齐 |
| 后续动作 | 对象、负责人、预算/数量边界、复查日；写入动作另核当前授权 |

## 合成验收案例

以下均为虚构情境，不是作者原例或店铺业绩。

| 场景 | 输入/变化 | 正确处理 |
| --- | --- | --- |
| 1 | 本月扣三个月前货损 | 回归原订单批次。 |
| 2 | 已净额发票再扣Allowance | 标重复扣除。 |
| 3 | USD已付但银行换汇未完 | 分别记录付款与到账。 |

完成时逐项回看输入、决定和交付是否对应；上传、审核、业务处理、物流与资金结果分别验证，不能用中间状态代替最终状态。
