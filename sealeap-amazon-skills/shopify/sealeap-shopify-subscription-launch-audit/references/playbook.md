# 操作手册

以下分支、数据字段和合成案例为M（模型独立综合）；E与R的有限支持范围见 [证据文件](evidence.md)。

## 分支判断

| 观察情况 | 下一步 | 必须避免的误判 |
| --- | --- | --- |
| 计划存在但页面无选项 | 检查目标商品/变体、主题组件与市场发布状态 | 后台创建不能当作买家可订阅 |
| 页面有选项但合同未验收 | 检查真实结账能力、支付条件和合同记录 | 不以页面截图证明扣款或续期成功 |
| 订阅与组合同时提出 | 核实际应用与当期兼容条件 | 不假定所有Bundle可直接订阅 |

## 交付工作表

| 交付项 | 必须保留 |
| --- | --- |
| 计划-商品映射 | 对象与版本、事实/口径、结论、未知项、负责人和下一次验收 |
| 购买与管理路径验收表 | 对象与版本、事实/口径、结论、未知项、负责人和下一次验收 |
| 首单/续期条件差异 | 对象与版本、事实/口径、结论、未知项、负责人和下一次验收 |
| 上线HOLD项与恢复办法 | 对象与版本、事实/口径、结论、未知项、负责人和下一次验收 |

每个状态都写观察时间；没有发生的动作使用“拟议/待核”，不能写“已完成”。公开报告用匿名代号，原始账户、订单和客户资料留在用户授权范围内。

## 合成案例

### 场景1

输入：顾客看到“每月两次”，后台间隔14天。

应有处理：标记周期表达不一致，修正文案或真实计划后复核。

### 场景2

输入：退款了一笔首单，但合同仍Active。

应有处理：分别决定退款、合同与未来履约，不能宣称已取消订阅。

### 场景3

输入：用户只要求验收。

应有处理：使用预览或测试数据，不新建真实付费订阅。


## 验收与停止

逐项检查交付是否能追到输入事实。遇到身份不匹配、决定性字段缺失、许可不足或超出用户授权时，停止受影响动作，列明补证与可继续部分。对批量变更保留目标清单、前后值、作用范围和恢复办法；单次请求成功不替代实际结果。
