# 操作手册

以下分支、数据字段和合成案例为M（模型独立综合）；E与R的有限支持范围见 [证据文件](evidence.md)。

## 分支判断

| 观察情况 | 下一步 | 必须避免的误判 |
| --- | --- | --- |
| 库存不足且卡片有效 | 优先修库存与履约条件 | 不要把所有失败归为支付问题 |
| 重试耗尽 | 核跳过/暂停/取消所对应的真实状态 | 不得假定退款会自动取消合同 |
| 重复账单事件 | 按尝试ID与周期去重，并查既有订单 | 不得再次建议收取同一周期费用 |

## 交付工作表

| 交付项 | 必须保留 |
| --- | --- |
| 合同事件时间线 | 对象与版本、事实/口径、结论、未知项、负责人和下一次验收 |
| 失败分类与处理建议 | 对象与版本、事实/口径、结论、未知项、负责人和下一次验收 |
| 重试/通知变更草稿 | 对象与版本、事实/口径、结论、未知项、负责人和下一次验收 |
| 未对平状态清单 | 对象与版本、事实/口径、结论、未知项、负责人和下一次验收 |

每个状态都写观察时间；没有发生的动作使用“拟议/待核”，不能写“已完成”。公开报告用匿名代号，原始账户、订单和客户资料留在用户授权范围内。

## 合成案例

### 场景1

输入：库存为零，系统没有创建续期订单。

应有处理：标为库存阻塞；补货预计时间不等于已可售。

### 场景2

输入：同一失败通知收到两次。

应有处理：只生成一次待处理任务，保留原始事件来源。

### 场景3

输入：客户已取消，旧失败邮件排队中。

应有处理：排除后续营销/催款并核既有订单责任，不强制恢复合同。


## 验收与停止

逐项检查交付是否能追到输入事实。遇到身份不匹配、决定性字段缺失、许可不足或超出用户授权时，停止受影响动作，列明补证与可继续部分。对批量变更保留目标清单、前后值、作用范围和恢复办法；单次请求成功不替代实际结果。
