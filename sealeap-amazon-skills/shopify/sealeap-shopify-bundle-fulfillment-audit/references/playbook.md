# 操作手册

以下分支、数据字段和合成案例为M（模型独立综合）；E与R的有限支持范围见 [证据文件](evidence.md)。

## 分支判断

| 观察情况 | 下一步 | 必须避免的误判 |
| --- | --- | --- |
| 组件全部有数量 | 按每套用量计算最少可完成套数 | 不能只取最少组件件数 |
| 某组件不追踪/允许超售 | 展示平台计算排除项和实际供应风险 | 不能输出无限库存或自动GO |
| 组合在渠道不可见 | 核渠道/应用能力和发布状态 | 不能仅反复发布组件 |

## 交付工作表

| 交付项 | 必须保留 |
| --- | --- |
| 组件与数量矩阵 | 对象与版本、事实/口径、结论、未知项、负责人和下一次验收 |
| 渠道/购买选项兼容表 | 对象与版本、事实/口径、结论、未知项、负责人和下一次验收 |
| 拆单与部分退货验收 | 对象与版本、事实/口径、结论、未知项、负责人和下一次验收 |
| 可售估算和实际供应差异 | 对象与版本、事实/口径、结论、未知项、负责人和下一次验收 |

每个状态都写观察时间；没有发生的动作使用“拟议/待核”，不能写“已完成”。公开报告用匿名代号，原始账户、订单和客户资料留在用户授权范围内。

## 合成案例

### 场景1

输入：合成：A有11件每套需2，B有7件每套需1。

应有处理：可完成套数为min(floor(11/2),7)=5；该结果仍需验证预留与履约。

### 场景2

输入：订单支付后只发出一个组件。

应有处理：分别核履约行与剩余承诺，不能把整套标完成。

### 场景3

输入：页面组合标题相同但组件SKU改了。

应有处理：检查旧映射是否失效，并按当前应用流程准备修复。


## 验收与停止

逐项检查交付是否能追到输入事实。遇到身份不匹配、决定性字段缺失、许可不足或超出用户授权时，停止受影响动作，列明补证与可继续部分。对批量变更保留目标清单、前后值、作用范围和恢复办法；单次请求成功不替代实际结果。
