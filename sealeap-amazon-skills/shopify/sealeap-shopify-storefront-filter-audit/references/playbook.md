# 操作手册

本页为独立编写的 M（模型综合）流程与合成案例；网络经验与规则的实际支持范围见[证据文件](evidence.md)。

## 分支定位

| 观察 | 优先验证 | 可作的判断 |
| --- | --- | --- |
| 应用里有，页面没有 | 主题支持、目标模板启用、当前集合适用数据 | 配置存在；显示结果未通过 |
| 颜色出现两个入口 | 原始选项名、空格、不同数据源和翻译 | 先明确映射，再决定规范化范围 |
| 组合筛选后仍没有合适尺码可买 | 商品级/变体级来源、库存、所选条件 | 商品被返回不等于具体变体能满足需求 |
| 换语言或币种后入口消失 | 当前官方限制、市场发布与翻译状态 | 已知能力限制和故障应分别记录 |
| 选择条件后没有结果 | 样本是否具备字段、条件逻辑与商品可售状态 | 不以一次零结果推断没有市场需求 |

## 配置与数据分开变更

先导出或记录旧字段、旧显示名、原始取值、受影响商品和依赖。修正显示名通常不等于合并底层选项；批量改源字段前检查变体、翻译、集合和应用依赖。不能为消除重复筛选而盲目重建变体。

基础用例至少覆盖：单值、同字段多值、跨字段多值、缺值商品、无货变体、清空条件。当前默认常见逻辑是同字段 OR、跨字段 AND，但部分字段可配置；以当前配置和实际结果共同确认，不在测试中强行套统一逻辑。

## 验收记录

| 字段 | 内容 |
| --- | --- |
| 页面范围 | 集合/搜索、主题版本、市场、语言、币种、设备 |
| 样本 | 匿名商品、期望变体、原始属性、可售状态 |
| 操作 | 条件及先后顺序；是否重置旧条件 |
| 结果 | 返回商品、是否可买、入口显示、截图观察时间 |
| 分类 | 通过 / 配置问题 / 数据问题 / 能力限制 / 待复核 |
| 变更 | 原值、目标值、依赖、验收人与恢复条件 |

修复后的转化变化只能先作观察性比较；活动、流量来源和库存不同会影响结果，不把筛选调整直接归因为增长。

## 易错场景（合成）

1. 应用中启用了材质筛选，草稿主题能显示但线上仍缺失。结论是线上主题验收未通过；不能凭草稿截图宣告完成。
2. 两个颜色筛选来自一个带尾空格的选项名。先评估依赖并在样本修复，不能只改显示名后声称源数据已合并。
3. 红色只有小码、蓝色只有大码，商品被某组合条件返回。检查具体可购变体和字段层级，将需求无法满足记录为验收失败；不要凭商品卡存在判成功。
