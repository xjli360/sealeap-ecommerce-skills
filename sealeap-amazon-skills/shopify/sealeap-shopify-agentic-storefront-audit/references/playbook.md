# 判读与合成案例

以下为SeaLeap的M工作流设计；官方依据见[证据文件](evidence.md)。

## 决策矩阵

| 观察 | 处理 | 不能推出 |
| --- | --- | --- |
| Catalog资格未知 | 取当前后台原因及计划类型，继续可做的公开样本检查 | 因网页能打开就认为有资格 |
| 能发现但不能结账 | 分查渠道购买方式、国家、库存和配送 | 已打通AI销售 |
| 标题来自自定义字段 | 对照实际Catalog映射与变体分组后给修复草稿 | 只改SEO摘要即可修复 |
| 只用第三方应用隐藏批发价格 | 取AI渠道商品证据并核原生B2B配置/排除能力 | 未登录看不到价格就不会被AI发现 |
| robots阻止抓取 | 另核Catalog和其他主动Feed | 所有AI渠道已彻底隐藏 |
| 已退出某渠道Catalog分发 | 复查已知外部索引及其他Feed | 立即从所有AI回答消失 |

## 验收记录

一行一个渠道×市场×商品变体：观察时间、资格证据、数据来源、真实价格/币种/库存、AI端显示、购买入口、结果、缺口、拟议变更、回读与恢复。禁止用一次未搜索到当完全排除证明。

## 合成场景

1. 商家只允许只读检查，AI显示价格错误：输出映射问题和草稿，不开关渠道或真实下单。
2. 商品在AI里可见，但直接结账仍在分批开放：标记发现通过、该购买方式待核，可检查已有跳转路径。
3. 批发应用只在主题中隐藏价格：检查分发和实际发现，不宣称B2B排除已生效。
4. robots已禁爬，但Catalog仍开启：指出两个通道独立，列对象级处理方案，不承诺全网立刻移除。
5. 用户提供一张AI截图而无SKU/市场：可辨认截图问题，金额与变体结论保持待核。

真实发布、修改渠道和测试购买只在该任务授权范围内执行；已有授权无需重复确认同一动作。记录提交与最终状态，结果不明确时先查询，避免重复变更。
