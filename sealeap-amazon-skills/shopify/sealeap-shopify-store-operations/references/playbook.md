# 操作手册

以下流程细化、计算和合成案例均为 M（模型综合设计），来源支持范围见 [证据与规则](evidence.md)。

## 诊断矩阵
| 现象 | 先检查 | 可验证动作 |
| --- | --- | --- |
| 访问增加、订单不增 | 新流量的国家、设备与意图 | 在同一分群比较漏斗 |
| 商品页到加购低 | 规格、价格、交期、信任证据 | 改一个疑虑点并记录版本 |
| 加购正常、结账少 | 意外运费、登录要求、变体缺货 | 用测试模式走完整路径 |
| 到结账、支付低 | 支付方式、配送覆盖、错误日志 | 重现具体失败条件 |
| 下单正常、利润下降 | 折扣、退款、履约、广告获客 | 用留存净订单重算贡献 |
| 邮件营收高但总额不变 | 归因窗口及重复认领 | 看订单去重和对照表现 |

## 运营动作边界
页面只用已验证的产品事实和真实评价；评价展示不制造身份或数量。商品 feed 的价格、库存、币种应与落地页一致。SEO 优先可索引、清楚分类和有用的独特内容，不机械生成大量近似页面。
每个 SKU 记录可售、预留、在途、补货交期和售后原因。库存天数要说明销量时间窗；新品无销量时不能用除零结果自动补货。

## 实验与留存（M）
先明确主要指标，例如每合格会话贡献，而不是同时追十个显著结果。固定分群与时间窗、记录促销和渠道变化。样本少时报告不确定性；能做随机实验才使用因果表述。
邮件可拆欢迎、弃单、购买后使用和复购提醒，但发送范围以同意状态为准；订单交付通知与营销不要混淆。LTV 用已观察 cohort 的净贡献和观察期限表示，尚未成熟的复购不可作为确定收入。

## 示例（合成数据）
全站转化率从 2% 降至 1.5%，同时低转化国家流量占比翻倍；原主要国家内转化不变。先报告流量组合变化，不直接重做商品页。
