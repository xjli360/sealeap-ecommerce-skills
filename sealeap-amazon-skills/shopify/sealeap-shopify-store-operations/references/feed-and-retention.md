# 商品 Feed、供应交接与留存

X01 支持商品资料与标签协同，X06 支持围绕购买任务组织内容，Z05/Z06 支持供应交接和邮件分型。以下检查表为 M；字段规则用 R15、邮件口径用 R18 校正，见 [证据与规则](evidence.md)。

## 商品资料只有一套事实，输出字段分别维护

| 层次 | 维护内容 | 验收证据 |
| --- | --- | --- |
| 商品事实 | 规格、材质、适用条件、变体、价格与库存 | 样品或业务事实依据及变体匹配 |
| 页面 | 标题、描述、规格、图片说明、交付与售后 | 对应国家/语言/变体的实际页面 |
| 搜索摘要 | 页面 SEO 标题与 meta description | 页面输出和搜索展示预期；展示由搜索引擎决定 |
| Merchant Center | 标题、描述、ID、链接及商品属性 | 实际送出字段、诊断结果、落地页一致性 |
| 经营标签 | 库存状态、测试组、贡献档位等 | 标签定义、负责人、更新时间与用途 |

不要把 SEO meta description 自动当作 Merchant Center 的 description，也不要假设 Shopify tag 会自动变成 Google custom label。先看当前连接器映射与实际输出。对 AI 生成的商品字段另核结构化字段要求，不能仅改可见文案就声称完成。

抽查不同变体、缺货和促销状态。处理结果按“提交 → 同步处理 → 可见结果”记录；同步成功不等于获得展示。需要改价、改库存或发布时沿用用户的实际授权范围。

## 发货交接保留必需信息

设计供应方交接表：内部订单引用、商品与数量、发货必需收件信息、约定时限、追踪号及异常状态。分析报告改用匿名订单代号，不拷贝姓名、联系方式和详细地址；发货数据只走用户已授权的供应方渠道。退款/取消变更要同步到待发货队列，避免已取消订单仍被执行。

验收关注规格、包装、追踪可用性、实际交期及售后责任，不接受供应商一句“已发货”代替可核查进度。

## 内容与邮件按任务诊断

内容需求按“怎么选、如何比较、怎么用、常见疑问”归档，每篇对应相关产品页和下一步。先处理断链、错误变体、缺规格、购买障碍，再决定是否扩写内容；关键词覆盖数量不代表访问或订单。

邮件分交易通知、营销活动、事件触发；触发事件不能替代营销同意。核对同意状态、退订抑制、已购买排除和事件去重，再形成待审草稿。

统一报表时写全分母：点击人数/送达人数，点击人数/打开人数。打开受隐私预加载影响，不依固定打开率判优。另列订单归因窗口、退款后贡献、退订和投诉；营销工具归因收入不等于新增收入。测试一次主要改变主题、内容或发送时机，并预先约定最大频率与停止条件。
