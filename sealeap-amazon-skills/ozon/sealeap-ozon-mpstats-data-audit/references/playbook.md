# MPstats 接入与数据验收判断与验收

## 数据到判断

从 `Ozon → Поиск по SKU；API full / by_period；或已授权 MCP 的 OZON 只读工具` 取得 SKU、updated、报告日期、FBS 开关、price 三种价格、no_data、sales、revenue；内部模块另标 actual。先固定样本、SKU/模型映射和分析周期，再执行主流程；保存被排除的行与原因。原始表的字段或时间口径改变后，旧分析不可直接复用。

本任务判定：READY 仅表示数据验收；鉴权失败、单位未知或采集缺口影响核心指标时 HOLD，保留可运行的补数请求。

## 输出结构

| 区块 | 必填内容 |
| --- | --- |
| 范围 | 地区、模式、SKU/细分、分析日期与覆盖率 |
| 证据 | MPstats报表/原始字段/数据时间/行键；实际与估算分开 |
| 判断 | 能力清单、字段映射、数据清单及哈希、分页/缺口审计、可计算指标、HOLD 原因 |
| 反证 | 哪个观察会推翻判断，缺什么数据会改变结论 |
| 行动 | 优先级、负责人、依赖、损失上限、复查日；需要写入时列明对象 |

没有强制填满所有判断：关键字段缺失时保留 UNKNOWN；明确请求报表名、日期、列和账户范围，方便补数。不可使用模型生成的行业平均值冒充 MPstats 查询结果。

## 合成案例

以下为编辑验收用虚构情境，既非作者案例，也非真实经营结果。

| 场景 | 输入/变化 | 预期处理 |
| --- | --- | --- |
| 1 | 输入 WB 数据但 SKU 为数字 | 拒绝平台错配，数字格式不证明 OZON 身份。 |
| 2 | API 返回 HTTP 200 且 error 字段非空 | HOLD，不输出零销量。 |
| 3 | 同一 SKU 同一天两行且金额差 100 倍 | 先解决重复和货币单位，不求平均。 |

## 完成条件

- 能从交付中的关键判断回溯到本任务所需的 MPstats 数据，而非只在文首提到服务名。
- 判断遵循上述分支，缺失和不适用数据未混入分母；没有复制竞品内容或公开私有订单。
- 用户收到可验证的下一步；HOLD时也有具体缺口、原因及恢复条件。
