# 评论痛点与产品改进定义判断与验收

## 数据到判断

从 `SKU → Отзывы；商品日序列与可比 SKU 清单` 取得 date、valuation、text、comments、rating、SKU、sales 与库存时间轴。先固定样本、SKU/模型映射和分析周期，再执行主流程；保存被排除的行与原因。原始表的字段或时间口径改变后，旧分析不可直接复用。

本任务判定：仅物流抱怨不支持更改产品结构；安全或性能声称无实验依据时 HOLD。

## 输出结构

| 区块 | 必填内容 |
| --- | --- |
| 范围 | 地区、模式、SKU/细分、分析日期与覆盖率 |
| 证据 | MPstats报表/原始字段/数据时间/行键；实际与估算分开 |
| 判断 | 匿名主题表、样本与偏差、产品需求、样品验收标准、成本与需求验证计划 |
| 反证 | 哪个观察会推翻判断，缺什么数据会改变结论 |
| 行动 | 优先级、负责人、依赖、损失上限、复查日；需要写入时列明对象 |

没有强制填满所有判断：关键字段缺失时保留 UNKNOWN；明确请求报表名、日期、列和账户范围，方便补数。不可使用模型生成的行业平均值冒充 MPstats 查询结果。

## 合成案例

以下为编辑验收用虚构情境，既非作者案例，也非真实经营结果。

| 场景 | 输入/变化 | 预期处理 |
| --- | --- | --- |
| 1 | 100条评分只有20条有文本 | 文本比例分母为20。 |
| 2 | 差评集中物流破损 | 优先包装与履约诊断。 |
| 3 | 用户说防水而规格未证实 | 不写防水卖点。 |

## 完成条件

- 能从交付中的关键判断回溯到本任务所需的 MPstats 数据，而非只在文首提到服务名。
- 判断遵循上述分支，缺失和不适用数据未混入分母；没有复制竞品内容或公开私有订单。
- 用户收到可验证的下一步；HOLD时也有具体缺口、原因及恢复条件。
