# 竞争格局与可比商品池判断与验收

## 数据到判断

从 `目标 niche → Продавцы / Бренды / Товары；SKU → Похожие товары` 取得 seller_id、brand、SKU、规格、sales、revenue、价格、在库天数。先固定样本、SKU/模型映射和分析周期，再执行主流程；保存被排除的行与原因。原始表的字段或时间口径改变后，旧分析不可直接复用。

本任务判定：样本过窄不能宣布蓝海；同款只支持竞争分析，不授予跟卖、复制图片或商标使用权。

## 输出结构

| 区块 | 必填内容 |
| --- | --- |
| 范围 | 地区、模式、SKU/细分、分析日期与覆盖率 |
| 证据 | MPstats报表/原始字段/数据时间/行键；实际与估算分开 |
| 判断 | 冻结竞品池、纳入排除原因、卖家/品牌双视图、集中度分母、差异化待验证项 |
| 反证 | 哪个观察会推翻判断，缺什么数据会改变结论 |
| 行动 | 优先级、负责人、依赖、损失上限、复查日；需要写入时列明对象 |

没有强制填满所有判断：关键字段缺失时保留 UNKNOWN；明确请求报表名、日期、列和账户范围，方便补数。不可使用模型生成的行业平均值冒充 MPstats 查询结果。

## 合成案例

以下为编辑验收用虚构情境，既非作者案例，也非真实经营结果。

| 场景 | 输入/变化 | 预期处理 |
| --- | --- | --- |
| 1 | 一个卖家经营三品牌 | 卖家份额合并，品牌视图另列。 |
| 2 | 只取前50却有1000商品 | 标前50样本份额。 |
| 3 | AI相似结果混入配件 | 从核心竞品池移出。 |

## 完成条件

- 能从交付中的关键判断回溯到本任务所需的 MPstats 数据，而非只在文首提到服务名。
- 判断遵循上述分支，缺失和不适用数据未混入分母；没有复制竞品内容或公开私有订单。
- 用户收到可验证的下一步；HOLD时也有具体缺口、原因及恢复条件。
