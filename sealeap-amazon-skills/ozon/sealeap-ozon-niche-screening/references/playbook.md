# 细分市场筛选与进入评审判断与验收

## 数据到判断

从 `Ozon → Выбор ниши → Товары / Продавцы / По дням` 取得 niche_id、SKU、sales、revenue、items、items_with_sells、卖家份额、在库天数。先固定样本、SKU/模型映射和分析周期，再执行主流程；保存被排除的行与原因。原始表的字段或时间口径改变后，旧分析不可直接复用。

本任务判定：GO 仅指进入有损失上限的试验；负贡献为 NO-GO，只有大盘或断货潜力没有可比商品证据为 HOLD。

## 输出结构

| 区块 | 必填内容 |
| --- | --- |
| 范围 | 地区、模式、SKU/细分、分析日期与覆盖率 |
| 证据 | MPstats报表/原始字段/数据时间/行键；实际与估算分开 |
| 判断 | 候选评分表、淘汰理由、样本分层、单位经济输入清单、试销上限与退出条件 |
| 反证 | 哪个观察会推翻判断，缺什么数据会改变结论 |
| 行动 | 优先级、负责人、依赖、损失上限、复查日；需要写入时列明对象 |

没有强制填满所有判断：关键字段缺失时保留 UNKNOWN；明确请求报表名、日期、列和账户范围，方便补数。不可使用模型生成的行业平均值冒充 MPstats 查询结果。

## 合成案例

以下为编辑验收用虚构情境，既非作者案例，也非真实经营结果。

| 场景 | 输入/变化 | 预期处理 |
| --- | --- | --- |
| 1 | 大类增长但目标细分下滑 | 不用大类增长支持进场。 |
| 2 | 高缺货潜力集中在一款品牌商品 | 只记录观察，不当作可抢份额。 |
| 3 | 证据充分但认证尚未核清 | HOLD，先补资格。 |

## 完成条件

- 能从交付中的关键判断回溯到本任务所需的 MPstats 数据，而非只在文首提到服务名。
- 判断遵循上述分支，缺失和不适用数据未混入分母；没有复制竞品内容或公开私有订单。
- 用户收到可验证的下一步；HOLD时也有具体缺口、原因及恢复条件。
