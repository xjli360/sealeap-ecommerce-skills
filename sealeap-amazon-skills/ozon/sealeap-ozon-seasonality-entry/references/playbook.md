# 季节窗口与上新倒排判断与验收

## 数据到判断

从 `niche → Тренды / По дням / Сравнение периодов；关键词频次趋势` 取得 date、end_date、sales、revenue、items_with_sells、库存、同周期频次。先固定样本、SKU/模型映射和分析周期，再执行主流程；保存被排除的行与原因。原始表的字段或时间口径改变后，旧分析不可直接复用。

本任务判定：仅有一个旺月不宣称稳定季节规律；预计可售时间晚于需求窗口且无常年用途则 NO-GO。

## 输出结构

| 区块 | 必填内容 |
| --- | --- |
| 范围 | 地区、模式、SKU/细分、分析日期与覆盖率 |
| 证据 | MPstats报表/原始字段/数据时间/行键；实际与估算分开 |
| 判断 | 季节曲线、窗口依据、日期倒排、延迟情景、补货截止与尾货方案 |
| 反证 | 哪个观察会推翻判断，缺什么数据会改变结论 |
| 行动 | 优先级、负责人、依赖、损失上限、复查日；需要写入时列明对象 |

没有强制填满所有判断：关键字段缺失时保留 UNKNOWN；明确请求报表名、日期、列和账户范围，方便补数。不可使用模型生成的行业平均值冒充 MPstats 查询结果。

## 合成案例

以下为编辑验收用虚构情境，既非作者案例，也非真实经营结果。

| 场景 | 输入/变化 | 预期处理 |
| --- | --- | --- |
| 1 | 单年促销导致峰值 | 标事件峰值，等历史复核。 |
| 2 | 旺季剩20天、供货需45天 | 不作正常旺季补货。 |
| 3 | 订单额涨但数量平 | 先核价格变化。 |

## 完成条件

- 能从交付中的关键判断回溯到本任务所需的 MPstats 数据，而非只在文首提到服务名。
- 判断遵循上述分支，缺失和不适用数据未混入分母；没有复制竞品内容或公开私有订单。
- 用户收到可验证的下一步；HOLD时也有具体缺口、原因及恢复条件。
